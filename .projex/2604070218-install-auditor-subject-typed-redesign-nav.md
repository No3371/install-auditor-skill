## Vision

`install-auditor` becomes a **dispatcher** skill: a small `SKILL.md` that classifies the subject of an audit (registry package, browser extension, container image, CI action, IDE plugin, desktop app, CLI binary, agent extension, remote integration, or generic), then loads exactly one `workflows/<subject-type>.md` whose rubric, evidence acquisition, and tier thresholds are tuned to that subject's actual risk surface. Shared verdict logic, the audit-coverage report, the `references/` rubrics, and the `registry-lookup.ps1` primitive remain shared. The end state: an auditor that gets *more rigorous* per subject while reading *fewer tokens* per audit, and that can absorb new subject types and new audit signals as additive workflow files instead of dilutions of one shared spine.

## Current Position

**As of 2026-04-17:**

The skill is a working dispatcher with live subject-specific workflows for all nine non-generic types: registry-package (Type 1), browser-extension (Type 2), ide-plugin (Type 3), container-image (Type 4), ci-action (Type 5), desktop-app (Type 6), cli-binary (Type 7), agent-extension (Type 8), and remote-integration (Type 9). `SKILL.md` classifies subjects (Step 0), loads per-type workflows (Step 1), and applies the shared verdict tree + audit-coverage report (Step N). Four data primitives support Type 1: `scripts/registry-lookup.ps1`, `scripts/typosquat-check.ps1`, `scripts/vuln-lookup.ps1`, and `scripts/dep-scan.ps1`. Each has a stdlib-only Python 3.8+ twin (`scripts/registry-lookup.py`, `typosquat-check.py`, `vuln-lookup.py`, `dep-scan.py`) with the same flags and JSON contract; runtime docs invoke the Python form first and name the `.ps1` twin for PowerShell hosts. The criteria layer is split: `references/criteria.md` (shared core) + nine per-subject addenda (`references/criteria/registry-package.md`, `references/criteria/browser-extension.md`, `references/criteria/container-image.md`, `references/criteria/ci-action.md`, `references/criteria/ide-plugin.md`, `references/criteria/desktop-app.md`, `references/criteria/cli-binary.md`, `references/criteria/agent-extension.md`, `references/criteria/remote-integration.md`). `workflows/generic.md` is now the low-confidence fallback only — all named types have dedicated workflows. Eval coverage is 26 cases (ids 0–25): three browser-extension (1, 10, 11), two container-image (12, 13), two ci-action (14, 15), two ide-plugin (16, 17), two desktop-app (18, 19), two cli-binary (20, 21), two agent-extension (id 22 Anthropic MCP filesystem server Tier 1 APPROVED; id 23 Discord-shared unknown MCP server Tier 3 REJECTED), two remote-integration (id 24 Slack official OAuth app Tier 1 APPROVED; id 25 phishing-distributed unknown vendor with overprivileged Google scopes Tier 3 REJECTED).
